# ADR-0035: 確定操作の成否を対象に結び付いた終端証拠と完了判断で決める

- 日付: 2026-09-25
- 状態: 採択
- 決定者: yo-xe + Claude Code

## 背景

E2E-01でアイコンのdouble clickによる起動やEnterによる送信の後、Finitactは成否を確定できず、Jevが同じ操作を
選び直していた(E2E-I3)。起動したアプリの窓はtarget(desktop)のframeの外に出るため、ADR-0030の達成判定E
(操作rect上の着地+Jevの事前適合)では見えない。yo-xeは用途分類(send・save等)で成功の証拠を決める案を出し、
consult(`docs/consult/20260925-2055-consult-commit-intent.md`)で反証を受けた。

## 決定

- 用途分類から直接successを出さない。成功は「対象に結び付いた終端証拠」AND「Jevの完了判断」の両方で決める。
- 終端証拠(機構が決定論的に判定)
  - 起動: 操作前に無かった可視top-level窓が前面に現れ、そのtitleかprocess名が押したlabelを含む。
  - 送信: goalの`fill_values`の文字が、操作前にあった場所から消え、別の場所に現れる(OCRの字間空白は無視、
    1割までの誤読を許容)。
- 完了判断は「同じgoalで既に済ませた操作に続けて、この操作がgoalを完了させるか」をJevに問う。
  Eの事前適合(この操作単独で満たすか)は複数手のgoalの最後の一手を不適合と答えたため使わない。
- 窓一覧は操作の前後にserverが取る(`list_windows`と同じ列挙)。証拠が無ければ`None`で、失敗にはしない。
- 対象はkey・click・double_click。click・fill・scrollはEの着地判定を優先し、その判断が無い時だけ使う。

## 検討した代替案(没案)

- 用途6分類ごとの固定規則: エラーダイアログも「窓増加+前面変更」を満たし、別名保存ダイアログは保存完了ではない(consult)。
- 任意の変化+Eの事前適合をkeyへ広げる: 事前適合は操作後の意味を見ておらず、エラー表示も成功に通す(consult)。
- 操作後の差分をJevに直接達成判定させる: ADR-0030で文字列の出現を達成と取り違えた記録がある。

## 影響

- E2E-01で起動goalのJev問い合わせが9回から4回になり、起動・送信とも`verified_success`で終わる。
- 保存・検索・ダイアログ確定・画面遷移は証拠が未定義で、従来通り`unverified`になる。途中状態への有限回の再観測は未実装。
