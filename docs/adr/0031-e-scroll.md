# ADR-0031: 達成判定Eの対象へscrollを加える

- 日付: 2026-09-25
- 状態: 採択
- 決定者: yo-xe + Claude Code

## 背景

達成判定E(ADR-0030追記1)はclick・fillだけを対象とし、screen pathのscrollは常に`unverified`だった。scrollは
画素変化域(`landed_conn`)では到達を読めない(枠全体が塗り替わる)ため、別の到達規則が要る。

## 決定

- scrollの到達は枠内の行の移動で読む(`scroll_shift`): 前後で一意な文字の行のうち2行以上が共通offsetで走査方向へ動く、
  または全行入替。走査方向へ動いた1行だけが残る4行以上の枠も全行入替と扱う。Jevの適合質問へは視界に入った行を渡す。
- 根拠: EXP-0008は枠下端の切れ行のOCR誤読(`entrv`/`entry`)で共有行が1行になり到達不一致1件で棄却。1行規則を足した
  EXP-0009で未見標本(字13/15/18×窓高さ380/540、6 case)36件の到達一致36/36・誤達成0件(`docs/experiments/0009-results.json`)。

## 検討した代替案(没案)

- 行文字の編集距離1を一致とみなす: 隣の行(`Item 14`/`Item 15`)を取り違え、静止した枠でも移動と読む。
- 枠の端で切れた行を照合から外す: 重なり2行の移動では残る共有行が1行で、到達不一致が解けない。
- keyを同時に対象へ加える: 対象rectが無く効果が別windowに出ることも多く、操作枠の前後比較では到達を観測できない。

## 影響

- `verified_success`はclick・fill・scrollで出る。key・drag終点観測・消えるpopup内の操作は引き続き判定対象外(None)。
- 横scroll・入れ子scroll・行の無い画像領域は未検証。
