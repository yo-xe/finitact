# ADR-0056: dragの終点で待ってから離す(E2E-05の0/3の原因)

- 日付: 2026-10-11
- 状態: 採択
- 決定者: yo-xe + Claude Code

## 背景

2026-10-11にE2E-05(Explorerのwindow間drag)がFinitactで0/3になった(10-04は5/5・41.6秒)。変更前コード(10-04 18:34時点)の対照も1/3で、
同日のFB対応(ADR-0055)やorb表示は原因でなかった。外側agentの報告はどれも「dragは送られたがファイルが動かない」。
候補の探索は正常だった(archive窓のフォルダ行は終点候補に出ていた)。

## 決定

`FinitactPointer.Drag`(`finitact/windows_screen_grounded.py`)は、終点へ着いたあと150ms待ってからボタンを離す。
切り分け: 同じ座標でwindows-mcpのdragは成功し、Finitactの`pointer.drag`は`True`を返してもファイルが動かなかった。待ちを足すと成功した。
終点が別processのwindowなので、drop先が「ポインタが上にある」ことを知る前に離していたと見る(OLE dragの終点通知の遅れ。直接の計測はしていない)。

結果: 修正後のE2E-05 Finitactは5/5・40.9〜51.7秒(基準 5/5・41.6秒)。

## 検討した代替案(没案)

- クイックアクセスの同名項目がおとりになった説: 試行ごとにフォルダ名を一意にしても0/3で、主因でない。名前の一意化は試験側に残した(同名の履歴を溜めない)。
- 中間moveを増やす: windows-mcpは0.06秒の速いdragでも成功したため、速度でなく終点での待ちが要る。
- 変更前コードへの戻し: 対照が既に失敗した。

## 影響

- dragが150ms長くなる。browser側のdragは別経路で変わらない。
- 対照の変更前コード3試行(成功1・失敗2)は`results.jsonl`のcommit欄がHEADのままなので外した。値は本ADRのとおり。
